# EvalMe 初始化体验设计

日期：2026-10-22
状态：已按独立 review 修订并完成本地实现；跨机新流程验收待执行。

## 目标与范围

让用户通过 `evalme-mvp init` 完成“这台设备可以使用 EvalMe”，无需理解连接 JSON、建表脚本或凭据文件权限。首次使用默认 SQLite；多设备共享选择已有 PostgreSQL。本文仅设计初始化，不改变 task/trial/grade 业务语义。

不安装 PostgreSQL、不创建数据库或数据库账号、不自动迁移或修复已有结构、不引入独立服务。高级文件参数保留，普通交互不再询问连接 JSON 或管理员 JSON 路径。

## 当前实现与需要修正的设计假设

当前初始化已使用 Clack，但 PostgreSQL 路径先询问连接 JSON，最后无条件询问管理员 JSON，使普通连接用户承担了部署概念。

当前 `mvp/src/config.mjs` 的 `assertRuntimePrivileges` 禁止应用账号拥有建表、对象所有权等高权限；运行时应保留最小权限。此前讨论的“应用账号有建表权限则直接初始化”与此约束冲突，本设计修正为：应用账号仅作日常读写；建表必须使用临时管理身份。不会为了简化向导放宽运行时权限。

## 用户场景

| 场景 | 用户操作 | 预期结果 |
| --- | --- | --- |
| 没有任何数据库服务，首次使用 | 选本机保存，接受默认位置 | 创建 SQLite 文件和结构，保存本机配置 |
| 已准备好的共享 PostgreSQL | 选共享，填写连接信息 | 只读检查结构与权限，保存应用账号连接 |
| PostgreSQL 目标数据库已存在，但无 EvalMe 结构 | 连接后按提示选择初始化 | 明确确认后，使用临时管理身份创建结构、授权；用应用账号重新验证 |
| 服务存在，但目标数据库不存在 | 查看明确错误 | 请管理员先创建数据库；不自动连接其他数据库建库 |
| 部分表存在、版本不兼容、对象冲突 | 查看检测结果 | 停止写入，提示管理员处理；不自动补表或迁移 |
| 网络、认证或权限失败 | 修改连接信息或退出 | 不误判为空库，不修改旧配置 |

## 交互流程

第一屏：

```text
◆ 你想如何保存学习数据？
│  ● 在这台电脑上保存（推荐，无需准备数据库）
│  ○ 连接 PostgreSQL（多台设备共享数据）
```

### 本机保存

显示默认 SQLite 路径，允许选择默认位置或自定义绝对路径。若已有兼容数据库，复用；初始化新库后验证成功才保存配置。切换已有配置指向时，展示旧、新目标并明确确认。取消不得删除旧库或旧配置。

### 连接共享 PostgreSQL

依次输入地址、端口（默认 5432）、数据库名（默认 evalme）、应用用户名（默认 evalme_app）、隐藏密码、TLS 方式（默认验证证书）。仅选择验证证书时提供可选 CA 路径。无默认私人地址或密码。

“不使用 TLS”需明确标注仅适用于本机或用户确认的私有网络；不能仅凭主机名或某个 IP 段判定网络可信。保留用户显式选择，不自动降级。

先显示“正在检查连接和数据库状态”，完成只读检测，再进入以下分支。

#### 已就绪

确认结构兼容、应用权限满足且无禁用的高权限。若已有本机配置且目标不同，先确认替换，再保存配置与密码，显示成功。整个路径不询问管理身份，也不执行 DDL、GRANT 或写入学习记录。

#### 未初始化

```text
◇ 已连接 PostgreSQL，当前数据库尚未初始化 EvalMe。
◆ 是否初始化这个数据库中的 EvalMe 结构？
│  ○ 初始化（需要管理员协助）
│  ● 暂不初始化
```

选择暂不初始化：明确说明连接尚未保存，退出且保留旧配置。

选择初始化：展示目标 host、port、database、schema（固定 evalme）、应用用户名；解释将创建 EvalMe 的表、索引和约束，并授予现有应用账号所需权限。不删除或覆盖已有对象，不创建用户、不修改密码、不撤销其他权限。

所有路径在远端写入前先确认旧、新本机连接的替换；同目标但重新输入凭据也需确认更新。拒绝时不进行远端初始化。

随后收集临时管理用户名、隐藏密码；复用同一目标和 TLS 设置，不能将管理员连接指向另一数据库。管理凭据仅驻留内存，禁止写入运行时配置、日志、诊断或命令历史。高级管理员文件参数的目标也必须进行一致性校验。

明确确认后：管理连接获得事务级互斥锁 → 在事务内重新检测状态 → 创建结构与最小授权 → 提交 → 用应用账号重新连接并验证 → 保存本机配置。

管理身份权限不足时说明缺少初始化权限，允许重试或退出。应用账号拥有被禁止的权限时不自动撤销，提示管理员调整或换用独立应用账号。

## PostgreSQL 状态检测契约

只查询固定 `evalme` schema，不依赖任意 search_path，不通过用户输入拼接 SQL 标识符。应用角色标识符在授权语句中使用安全引用。

- **READY**：版本标记符合支持版本；预期表、列、类型、必要约束和索引符合当前结构；应用账号拥有 schema USAGE、所有运行时需要的读取权限及五张业务表 INSERT，新初始化仅显式授予 schema_meta SELECT；已有 INSERT（含默认授权继承）保持兼容，不在本次流程撤销；无当前策略禁止的高权限。
- **UNINITIALIZED**：可确认没有任何 EvalMe 对象；schema 不存在，或 evalme schema 完全为空。数据库其他 schema 的无关表不影响判断。
- **INCOMPATIBLE**：出现部分对象、未知对象占用 evalme schema、同名非表对象、缺失或异常版本记录、结构不匹配、较新或较旧版本。返回简明原因，不调用 CREATE IF NOT EXISTS 掩盖差异。
- **PERMISSION_DENIED / UNKNOWN**：无法可靠读取目录、访问 schema 或确定结构时，提示权限或检查失败。对象不可见不等于对象不存在。允许管理员协助诊断，但不能直接推断可以建表。
- **连接错误**：区分网络/超时、认证、数据库不存在、TLS 验证失败，保留适合用户理解的原因，不输出连接串和密码。

对象清单与版本规则应来自同一份 schema 定义或兼容性契约，避免检测与建表实现各维护一份不一致的规范。不能仅以 schema_meta 存在判定已就绪。

## 一致性、失败与取消

- 建表和授权在同一 PostgreSQL 事务内完成；锁覆盖重新检测和创建，避免两台机器同时初始化。
- 若锁后发现另一设备已完成：不重复建表，重新校验并进入已就绪流程；若状态不兼容则回滚退出。
- DDL/授权失败或提交前取消：回滚远端事务，不保存本机配置。
- 远端提交成功但应用连接验证失败：提示“数据库结构已初始化，应用连接验证未通过，旧配置保持不变”，按网络或权限原因指导重试/管理员处理；不重复建表。
- 远端提交成功但本机保存失败：明确提示“数据库已初始化，本机配置未保存”，不要声称全部回滚；重新 init 可恢复。
- 提交结果因断线不明：报告结果未确认，下次只读重检，不盲目重复写入。
- 本机配置和生成密码采用临时文件、受限权限和原子替换；失败清理本次临时凭据，旧配置保持可用。不得清理外部提供的密码文件。
- Ctrl+C 在提示阶段显示取消，不保存输入；在数据库操作阶段按上述提交边界处理取消，关闭连接并恢复终端状态。

## 非交互与高级用法

已有 `--provider`、`--connection-file`、`--admin-connection-file`、`--json`、`--non-interactive` 保持兼容。只提供应用连接时不自动建表；现有显式管理员初始化参数仍表达初始化意图，但同样必须执行目标一致性、空库检查和事务保护。

机器模式不弹出提示、不因 stdin 缺失等待、不把 Clack 装饰混入 JSON。结构状态以稳定错误码和安全详情表达；新增错误码及退出码映射需在实现时列入协议文档和测试，不改变已有成功响应结构。

## 验收标准

1. 空白 HOME 使用默认 SQLite，不要求安装数据库服务，成功后 doctor 就绪。
2. 已就绪 PostgreSQL 仅应用身份完成；断言没有管理员提示、DDL、GRANT 或业务写入。
3. 空 PostgreSQL 数据库：拒绝初始化时零写入；确认后结构和授权完成，应用身份可用，配置中没有管理身份或密码。
4. 目标数据库不存在、认证失败、网络超时、TLS 失败分别给出对应错误，不进入空库初始化分支。
5. 部分表、缺少版本、错误列类型、缺少约束/索引、同名视图、未知对象、不可见对象均不会触发自动修复。
6. 管理权限不足、运行时账号权限过高、缺少读写权限或 schema USAGE 均阻止保存，并保持旧配置。
7. 两个进程同时初始化只产生一套完整结构；失败事务无残余对象。
8. 管理目标不一致、危险角色名不会产生跨目标操作或 SQL 注入。
9. 密码在输入、错误、取消、JSON 和日志中均不回显；管理凭据不落盘。
10. PTY 验证纵向单选、默认选项、方向键、回车、Ctrl+C、替换配置确认；非交互及已有高级参数回归通过。
11. 远端提交后模拟本机保存失败，提示准确；再次 init 可恢复，不影响已有学习数据。
12. 本机 SQLite、真实隔离 PostgreSQL 与公司电脑跨机验收分别记录，不互相替代。

## 实施顺序

先实现只读状态检测与测试，再接入交互分支，然后实现临时管理员事务初始化及异常恢复，最后更新使用说明和跨机验收。生产共享数据库不得作为空库或破坏性故障测试对象。

## 实现备注

使用只读 pg_catalog 检测和由实际 DDL 生成的结构契约，避免权限过滤视图将不可见对象误判为空。契约包含核心代码追加的外键，并由源码摘要和真实建表测试约束一致性。已验证 PostgreSQL 18；其他大版本尚未验收。CLI 的空库创建、授权与锁使用同一连接的同一事务，不嵌套原 Store.initialize 的独立提交。

已有库的 schema_meta INSERT 与管理角色默认授权保持兼容；只是不主动授予新库 metadata 写权限。管理权限不足可退出后修正并重新运行 init，不在同一次向导里反复收集管理密码。独立 review 报告保留原审查版本的行号与发现，作为设计修订记录。
